# Contributing

## No SWF content

AnySWF is a compiler and runtime only. Pull requests that add, link to, or embed
third-party SWF files, extracted assets, or anything converted from them (assets.bin,
generated game.c, EBOOTs, APKs, screenshots of commercial games) are closed without
review. The only SWFs in the repository are Ruffle's MIT/Apache test movies
(`tests/ruffle/`, `tests/ruffle-avm1/`); new test movies are written from scratch
(`tests/swf-src/*.as`, compiled with MTASC, or generated by
`swf2c/examples/gen_test_swfs.rs`).

## Testing a game and reporting results

1. Build the tools (see `README.md`), then the game for the targets you can test:

   ```sh
   anyswf build game.swf --target linux -o out/game-linux   # or windows / macos
   anyswf build game.swf --target psp   -o out/game-psp     # copy the folder to ms0:/PSP/GAME/
   anyswf build game.swf --target android -o out/game-apk
   ```

   Details and options: [docs/user/EXPORT.md](docs/user/EXPORT.md).

2. Play it. Note how far it gets, what looks or sounds wrong, and, on a PSP-3000, the
   frame rate. Run the PC build from a terminal and keep its log: the runtime reports
   problems (including ActionScript calls it does not implement) there by name.

3. Add or update `compat/<short-name>.toml` (format and stage rules:
   [compat/schema.md](compat/schema.md)) with `kind = "game"`, where the game comes
   from (a page, not a file), optionally `swf_sha256` of your file, the stage, the
   targets you tried, `psp_fps`, the unimplemented calls, and one line of evidence.
   Check it with `python tools/compat-site/generate.py`, which also writes the page to
   `out/compat-site/progress.html`.

4. Open a pull request with only the TOML change, or an issue with the same details
   if you are not sure about the stage.

## Code changes

- Read the relevant plan phase and `README.md` first; keep `platform/` free of
  Flash-specific code (it is shared with other PSP ports).
- Run the checks CI runs: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`
  and `cargo test` in `swf2c/`; `ctest` in a CMake build; the render tests
  (`tests/render/run.sh`); the AVM1 conformance runner (`tests/avm1/run-avm1-tests.py`);
  `python -m unittest discover -s tools/compat-site`.
- PSP-visible changes: also run `tests/psp/run-psp-corpus.py` under PPSSPPHeadless, and
  say whether you tested on hardware.
- Commits use conventional commit messages (`feat(runtime): ...`, `fix(swf2c): ...`).
